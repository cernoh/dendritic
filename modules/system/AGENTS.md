# system — cross-host system modules

## Purpose
NixOS modules shared by every desktop host (or available to any host). Composed by `attrs/desktop` and by hosts directly. Owns machine facts, HM wiring, and OS-level services.

## Ownership
Each subdirectory is one system concern exporting `flake.nixosModules.<name>`:

- `core/` — base system bundle, `nix-settings.nix` (caches, keep in sync with `flake.nix:nixConfig`), `boot.nix`, `hardware.nix`, `locale.nix`, `user.nix`; defines `flake.lib.hardwareFromMachine`.
- `home-manager/` — wires `inputs.home-manager` into NixOS, sets `useGlobalPkgs`/`useUserPackages`/`backupFileExtension`, enables the **all-host** HM feature set (`nvf`, `agent-browser`, `programming`, `fish`, `nushell`, `opencode`, `waylandBase`, `stylix`, `retrosmartCursor`) for `config.dendritic.userName`. A host-scoped HM feature must NOT be added to that list: `herdr`, `herdr-web`, `herdr-web-ui`, and `wayfinder-dashboard` ship their HM module from their own NixOS module through `home-manager.sharedModules`, so a host opts in by importing the NixOS module alone. Listing one here put both herdr bridges and their packages in ASAHI's closure. The `omp` feature still ships in the flake, but no host imports it.
- `distributed-builds/` — the NIXPC build link. `builder.nix` exports `remoteBuilder` (imported by `hosts/NIXPC`), `client.nix` exports `distributedBuilds` (imported by `hosts/ASAHI`), and both import `_link.nix` for the shared account, key path, address, and host key.
- `network/`, `audio/`, `drivers/` (`asahi.nix`, `nvidia.nix`), `portals/` (GNOME + WLR + GTK backends; the mango ScreenCast/Screenshot → wlr routing itself lives in the mangowm input module, imported by `features/mango`), `tailscale/`, `time-sync/`, `stability/`, `obs/`, `home-manager/` — one concern each. `audio/` also imports `self.nixosModules.easyeffects`, so the PipeWire stack and its effects app stay one enable switch. Declarative Flatpak ownership lives in `features/flatpak/`; `system/flatpak/` is gone, so this list no longer names it.
- `wayland.nix` — exports `flake.nixosModules.wayland`: the Wayland + XWayland toolkit (X11 and Wayland CLI tools, wlroots/Mango control tools, Qt and cursor glue, fcitx5 packaged but not enabled, graphics and decode diagnostics) plus the keychain pair (`polkit-gnome` agent, `services.gnome.gnome-keyring`, sudo and polkit auth caches). It imports `portals`, so it owns the portal stack for both hosts.
- `disk-health/` — SMART on hosts with real storage: `smartmontools` (smartctl), `services.smartd` over autodetected devices, and the noctalia drive-health plugin's read-only root collector as a declared `noctalia-drive-health.{service,timer}` pair. Opt-in per host (`hosts/NIXPC` imports it).
- `hardware-profiles/` — the nixos-hardware registry (`flake.nixosHardwareProfiles`) and its coverage matrix. Exports no NixOS module: hosts splice the selected profiles onto their `modules` list from `hosts/<HOST>/_hardware-profiles-settings.nix` → `modules/system/hardware-profiles/AGENTS.md`.

## Local Contracts
- **Naming:** `flake.nixosModules.<name>` matches the directory (e.g. `core`, `network`, `audio`, `homeManager`, `asahiPlatform`/`nvidiaDrivers` for drivers).
- **`core` is the root bundle:** `attrs/desktop` and hosts import `core`; `core/default.nix` itself composes submodules (`nix-settings`, `boot`, `hardware`, `locale`, `user`) via a local `modules` list — not via `hardwareFromMachine` (that is host-wired).
- **`hardwareFromMachine` lives in `core`:** `self.lib.hardwareFromMachine` is defined in `system/core/default.nix` but consumed in `hosts/*/default.nix` — not imported as a module directly.
- **`home-manager` module is `moduleWithSystem`-free for `desktop` but this module itself is plain:** it reads `config.dendritic.userName` to wire `home-manager.users.<name>`. It publishes no option-tree export for the editor any more: the `dendritic.nixdOptionTree` option existed only so nixd could complete this user's HM options, and nil (the current Nix LSP) evaluates the flake itself.
- **Cache lists are dual-homed:** `flake.nix:nixConfig.substituters`/`trusted-public-keys` and `system/core/nix-settings.nix` must stay in sync (handoff comment in both files).
- **`wayland.nix` is intentionally self-sufficient:** it ships the full Wayland/XWayland toolkit even where a feature (`mango`, `computer-use`, `clipboard`) already installs part of it. Do not deduplicate it against features; a duplicated package is cheap, a desktop whose debugging tools depend on an unrelated feature being enabled is not. Everything in its package list is *packaged*, not autostarted — only the polkit agent and gnome-keyring are services.
- **`hardware-profiles` is a registry, not a module.** It publishes `flake.nixosHardwareProfiles` (declared in `parts.nix` alongside `fonts`/`flatpakPackages`) and deliberately exports no `flake.nixosModules` entry, because a NixOS module cannot import conditionally on its own `config` and the upstream nixos-hardware profiles set their values unconditionally. Hosts therefore splice the chosen profiles onto `modules` statically, from their own `_hardware-profiles-settings.nix`. The coverage matrix in that directory's AGENTS.md is the record of what was considered and rejected; adding a registry row without a matrix row is not a complete change.
- **`wayland.nix` owns the portal stack for both hosts:** hosts import `wayland`, not `portals` directly. `portals` is still imported by `features/flatpak`, so it reaches hosts by that route too; the import is idempotent either way.
- **The keychain caches are time-boxed, never password-free:** `security.sudo.extraConfig` uses `lib.mkAfter` because nixpkgs already defines that string, and `security.polkit.settings.Polkitd.ExpirationSeconds` extends polkit's cache. `security.sudo.wheelNeedsPassword` stays on — the password is still required, just not retyped constantly. Do not wire an askpass helper that replays a stored password into sudo.
- **Build parallelism is pinned in `nix-settings.nix`, not `flake.nix`:** `max-jobs = 4` with `cores = 0`. NixOS's default (`max-jobs = auto`, `cores = 0`) oversells `nproc²` processes and degrades the box by context switching; `nixConfig` cannot carry these because they depend on the machine's core count. `cores = 0` is deliberate — it hands a single heavy derivation the whole box, which is what `linux-asahi` needs. ASAHI overrides both (`asahiConfiguration.nix`, 8 vCPU / 7.3 GiB RAM / zswap + 12 GiB disk swap). Revisit together with the RAM/cores of a new host, and never raise `max-jobs` without lowering the per-build core budget.
- **GC retention is a speed knob:** `programs.nh.clean.extraArgs` keeps 5 generations / 14 days. A collected path is a recompile on rollback, so narrowing this trades disk for build time.
- **The build link is one identity file, and its client half is retired.** `system/distributed-builds/_link.nix` still holds the `remotebuild` account, the `/root/.ssh/remotebuild` key path, the tailnet name of the builder, and its base64 host key, so `builder.nix` and `client.nix` cannot drift if the link is ever revived. Nothing imports the client half today: `hosts/ASAHI/default.nix` dropped `distributedBuilds` and forces `nix.buildMachines = []`, so ASAHI builds every derivation it installs itself. `builder.nix` stays wired on NIXPC but has no client. Keep the pair in place rather than deleting them — the base64 public key is committed, and `sshKey` must name a real file the repo cannot hold, so a revival needs a manual key install on the Mac first.
- **Feature gating no longer depends on a remote builder.** `nix.buildMachines.*.supportedFeatures` used to be load-bearing: the Asahi kernel carries `requiredSystemFeatures = [ "big-parallel" ]`, so the link's advertised feature decided whether the bootchain built on NIXPC or fell back to the Mac. ASAHI's own builder advertises `big-parallel` through nixpkgs' default `nix.settings.system-features`, so the bootchain builds locally either way. If that option is ever overridden, `big-parallel` must stay in it or `linux-asahi` becomes unbuildable on this host.
- **The polkit agent binary is under `libexec`, and the unit is not a D-Bus service.** `pkgs.polkit_gnome` installs `polkit-gnome-authentication-agent-1` at `$out/libexec/`, not `$out/bin/` — its own XDG autostart `.desktop` uses that path. A unit whose `ExecStart` names `bin/...` fails `203/EXEC` and leaves the session with no interactive authentication agent at all. The agent is a plain long-running client that registers with polkitd through the Authority, so the unit carries no `Type = "dbus"`/`BusName` (naming `org.freedesktop.PolicyKit1.Authority` would name polkitd itself). Noctalia's own agent (`shell.polkit_agent`, default `false`) stays off, so `polkit-gnome` is the single agent on both hosts.
- **`disk-health` declares the noctalia collector, because the plugin cannot install it on NixOS.** `smartmontools` + `services.smartd` (`-a -n standby`, so an idle HDD is not woken for a poll) plus the `noctalia-drive-health.{service,timer}` pair is the whole declarative surface. The plugin's `install-system-collector.sh` writes its unit files into `/etc/systemd/system`, which here is a symlink to the read-only `/nix/store/…-system-units`: the install dies with `Read-only file system` **after** staging its scripts into `/usr/local/libexec/noctalia-drive-health/`, which leaves the panel on `stale` with `installed = true` and no unit behind it. So the module declares the pair itself (`services.noctaliaDriveHealth.intervalMinutes`, default 15) and an activation script stages `collect_raw.sh` and `smart-action.sh` out of the user's materialized plugin tree into that same root-owned path — the plugin tests for `collect_raw.sh` before reporting "installed", and its full SMART is the JSON (`schema` 2, `collector_version` 2.0.1) the panel reads from `/run/noctalia-drive-health/raw.json`. Four things have to hold together:
  - **The unit carries its own PATH.** The collector calls `lsblk` and `smartctl` by bare name and nixpkgs' default service PATH (coreutils, findutils, gnugrep, gnused, systemd) has neither, so `lib.mkAfter` appends both to it. `RuntimeDirectoryPreserve = true` is load-bearing: without it systemd removes the cache directory when the oneshot exits.
  - **The runtime directory's group and mode are the read path.** `Group` comes from `config.users.users.<dendritic.userName>.group` with mode `0750`, so the desktop user reads `raw.json` (0640) without root.
  - **The three plugin lifecycle scripts are replaced at the plugin's own paths.** `manage-collector.sh`, `set-collector-interval.sh`, and `uninstall-collector.sh` all assume a writable `/etc/systemd/system` (`enable`/`disable`, a timer drop-in, an `rm -rf` uninstall), and the plugin re-issues `start` on every shell start, so leaving them in place means an error notification per login. The activation script symlinks NixOS-aware replacements over them: start/stop instead of enable/disable (a pause lasts until the next boot), a drop-in under `/run/systemd/system/`, and an uninstaller that stops the pair and names this module. The plugin's own install/upgrade button still cannot finish — using it needs a rebuild to restore the replacements.
  - Unprivileged `smartctl --all /dev/sd*`/`/dev/nvme*` is `Permission denied` — the package serves root and smartd, not the desktop user.

## Work Guidance
- New cross-host concern: create `system/<name>/default.nix` exporting `flake.nixosModules.<name>`; compose into `core` if every host needs it, or leave standalone for opt-in via `hosts/*/default.nix`.
- Driver variants go under `system/drivers/` (`asahi.nix`, `nvidia.nix`) — keep platform-specific packages isolated.
- When adding a substituter/key, update both `flake.nix` and `system/core/nix-settings.nix`.
- `nix.buildMachines.*.publicHostKey` takes base64 of the whole public key line (`base64 -w0 /etc/ssh/ssh_host_ed25519_key.pub`), because Nix tokenizes the machines file on whitespace and base64-decodes that field. Confirm a change with `nix build --impure --no-link --print-out-paths '.#nixosConfigurations.<HOST>.config.environment.etc."nix/nix.conf".source'`.

## Verification
- `nix-instantiate --parse modules/system/<name>/default.nix`
- `nix eval .#nixosConfigurations.<HOST>.config.<option> --impure` for the option the module sets.
- `nix eval --impure .#nixosConfigurations.NIXPC.config.services.smartd.enable` is true, and `smartmontools` is in `environment.systemPackages`.
- `nix eval --impure --raw .#nixosConfigurations.NIXPC.config.systemd.services.noctalia-drive-health.serviceConfig.ExecStart` names the staged `collect_raw.sh`, and `…config.systemd.timers.noctalia-drive-health.timerConfig.OnUnitActiveSec` is `<interval>min`.
- `nix eval --impure --raw .#nixosConfigurations.NIXPC.config.system.activationScripts.noctaliaDriveHealth.text` globs the materialized plugin directory and symlinks the three lifecycle replacements.
- `nix build --impure --no-link .#nixosConfigurations.NIXPC.config.system.build.separateActivationScript` — the activation builder runs a bash syntax check over the script above.
- `nix eval --impure --raw .#nixosConfigurations.<HOST>.config.systemd.user.services.polkit-gnome.serviceConfig.ExecStart` names `libexec/polkit-gnome-authentication-agent-1`, and that store path really contains the file. On a live host `systemctl --user is-active polkit-gnome` is `active`; a `203/EXEC` in `journalctl --user -u polkit-gnome` means the path is wrong.
- `nix flake check --impure` — hardware gate validates `hardwareFromMachine` branching.
