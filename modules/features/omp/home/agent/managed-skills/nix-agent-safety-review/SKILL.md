# Nix agent safety review

Use as the final review for any non-trivial Nix or flake change.

## Mandatory questions
- Is `flake.lock` committed, generated by Nix, and narrowly changed?
- Is the exact output, host, architecture, and platform identified?
- Are evaluation, build, and activation verified separately?
- Are overlays and `pkgs` instantiated consistently?
- Are module option types and merge priorities understood?
- Are secrets and mutable state absent from `/nix/store` and derivation arguments?
- Are input follows and duplicate nixpkgs revisions intentional?
- Would garbage collection preserve the required generation and closure?
- If cross or remote building is involved, are build/host/target roles and builder access verified?

## Evidence
Record the exact validation commands and distinguish observed results from assumptions. Do not call a successful evaluation a deployed or reproducible system.
