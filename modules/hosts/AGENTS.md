# hosts — host presets

## Purpose
One directory per machine producing `flake.nixosConfigurations.<HOST>`. Assembles `self.nixosModules` bundles + features into a concrete NixOS system. Two hosts: `NIXPC` (`x86_64-linux`, MangoWM, NVIDIA) and `ASAHI` (`aarch64-linux`, MangoWM + Niri, Apple Silicon).

## Ownership
- `NIXPC/` — `default.nix` (system assembly), `nixpcConfiguration.nix` (host-specific NixOS config), `_noctalia-settings.nix`, `_mango-settings.nix`, `_hardware-profiles-settings.nix`, `RESCUE.md` if present.
- `ASAHI/` — `default.nix`, `asahiConfiguration.nix`, `RESCUE.md`, `_noctalia-settings.nix`, `_mango-settings.nix`, `_hardware-profiles-settings.nix`.

## Local Contracts
- **Assembly is `nixosSystem`:** each `default.nix` calls `inputs.nixpkgs.lib.nixosSystem { system = "<arch>-linux"; modules = with self.nixosModules; [ … ]; }`.
- **`hardwareFromMachine` gate:** every host's first module is `(self.lib.hardwareFromMachine "<system>")` from `modules/system/core/default.nix`. On the native machine with `--impure`, it imports `/etc/nixos/hardware-configuration.nix` (real `fileSystems."/"` by-uuid, `nixpkgs.hostPlatform` from hardware). Anywhere else (CI, other host, sandbox/`CI=1`/`NIX_BUILD_TOP`) it uses a placeholder root fs — evaluation succeeds, deploy does not. The `verify.nix` hardware gate enforces this.
- **`--impure` required for deploy:** `sudo nixos-rebuild switch --impure --flake ~/.config/dendritic#<HOST>` — evaluated elsewhere shows the documented placeholder warning.
- **Shared base is `desktop`:** both hosts import `desktop` (from `attrs/desktop` → `core` + `network` + `audio` + `homeManager` + `act` + `waylandBase` + `computerUse` + `stylix` + `nautilus` + common `environment.systemPackages` + `allowUnfree`). Host `default.nix` then adds its compositor, drivers, and extras. Neither `stylix` nor `nautilus` is host-specific, so they live in the bundle rather than in a host's module list.
- **Per-host deltas:**
  - `NIXPC`: `nixpcConfiguration`, `nixpcDesktop`, `nvidiaDrivers`, `diskHealth` (smartmontools, smartd, and the noctalia drive-health collector unit), `gaming`, `mango`, `wayland`, `noctaliaGreeter --session Mango`, `mcpContainers` (via `desktop→act→docker`; do not re-import `docker`), `herdr` (the daemon itself: `herdr server` as a user service with `git` on its PATH, owned by a unit instead of by whichever client connects first), `herdr-web` with `services.herdr-web.tailscaleServe.enable = true` (the bridge reaches the phone over tailnet HTTPS), `herdr-web-ui` with `services.herdr-web-ui.tailscaleServe.enable = true` (the second, richer herdr client — chat view, file viewer, remote PCs, push alerts — on its own port, published alongside the first), `remoteBuilder` (the `remotebuild` build account, issue #209; dormant — ASAHI no longer schedules work here, see the build-link contract below), `paseo` (the daemon and web UI container behind `tailscale serve`, issue #201), `wayfinder-dashboard` (Wayfinder Relay user service behind `tailscale serve`, one Herdr workspace per project), `flatpakNixpc` (OBS Studio, Sober, and the pinned Spotifast and Nuvio release bundles — all x86_64-only).
  - `ASAHI`: `asahiConfiguration`, `asahiPlatform` (apple-silicon support), `widevine`, `niri`, `mango`, `wayland`, `noctaliaGreeter --session Mango`, `stability`/`timeSync`/`flatpakAsahi`/`obs` (the Flatpak feature contributes **no** apps on ASAHI: every app in it is x86_64-only and aarch64 has none). It builds **everything locally** — `distributedBuilds` was removed and `nix.buildMachines` is forced empty, so no derivation this host installs can be scheduled off-box.
- **NIXPC's data disks are reachable from home as plain symlinks:** `nixpcConfiguration.nix` sets `home.file."2tb-storage"/"2tb-ext4"/"endeavouros"` with `mkOutOfStoreSymlink` (no store copy of disk contents) and mirrors both mounts into `gtk-3.0/bookmarks`. `~/Downloads` is a fourth entry: it points at `/mnt/2tb-ext4/Downloads` so multi-GB archives (transmission, persepolis, browser) land off the NVMe root filesystem. home-manager will not clobber a real directory, so `~/Downloads` must be emptied and removed before the switch that introduces the symlink; on an absent data disk it dangles deliberately, so downloads fail loudly instead of silently refilling `/`.
- **The three agent-facing servers are NIXPC-only, and the import must stay that way.** `herdr-web`, `herdr-web-ui`, and `wayfinder-dashboard` each ship their home-manager module from their own NixOS module (`home-manager.sharedModules`), so `hosts/ASAHI/default.nix` must not import them. The herdr bridges grant terminal control of every pane to whoever reaches them, and ASAHI runs no agents. `herdr-web-ui` is doubly NIXPC-only: its `node_modules` FOD hash is the tree bun resolves for x86_64, so ASAHI's closure failed to build it with a hash mismatch. The `herdr` binary itself stays in `attrs/desktop`'s shared `systemPackages` — it is a multiplexer client, not a server.
- **Per-host keyboard layout is a three-channel contract.** `system/core/locale.nix` holds the `mkDefault` `gb`/`uk` pair for NIXPC. ASAHI overrides all three with the **UK Macintosh** keymap: `services.xserver.xkb.layout = "gb"` + `variant = "mac"`, `console.keyMap = "gb"` (`hosts/ASAHI/default.nix`), and `dendritic.mango.xkbRulesLayout = "gb(mac)"` (`hosts/ASAHI/_mango-settings.nix`), because the compositor's own keymap is the one that types. The variant follows **macOS UK typing, not the US ANSI keycaps** on the keyboard: Shift+3 = £, € and # are on the third level (`ISO_Level3_Shift`, i.e. Right Alt) of 2 and 3, while Shift+2 = @ and ` / ~ stay on the key next to left Shift because the `mac` variant defines them that way. **The physical fn key is remapped to Right Alt to reach that third level**, by a system-level `systemd.services.evremap` in `asahiConfiguration.nix` (`environment.etc."evremap.toml"`, `KEY_FN` → `KEY_RIGHTALT`), so fn+2 / fn+3 behave like macOS UK. Two facts make that possible and both are verified, not assumed: a MacBook's fn key reaches userspace as `KEY_FN` (0x1d0, read off `/dev/input/event1`), and `gb(mac)` includes `level3(ralt_switch)`, which binds Right Alt to `ISO_Level3_Shift`. It is a **system** service, not a session command: evremap grabs the device exclusively and `/dev/uinput` is root-only on this machine, and `Restart = "always"` covers the internal keyboard not being up at boot. No Home Manager key remapping, so Ctrl+2 stays Ctrl+2.
- **Both hosts import `wayland` (`system/wayland.nix`) and neither imports `portals` directly:** `wayland` imports `portals`, so it is the single entry point for the portal stack. The module is written against MangoWM, which both hosts run; the `niri` module on ASAHI is installed but not the session in use.
- **Flatpak is a feature, not a system module:** each host imports the `flatpak` feature (`flatpakNixpc` / `flatpakAsahi`), which carries the per-host Flatpak apps on top of the shared `flatpakCommon` aspect (service enable + weekly updates). `system/flatpak/` no longer exists.
- **Machine facts of a shared feature live in `_<feature>-settings.nix`:** the host module imports the file and assigns it to the feature's options. `mango` (issue #245) is the reference: each host imports `_mango-settings.nix` into `dendritic.mango`, because mango runs on both hosts but only NIXPC has two monitors and an NVIDIA GPU, only ASAHI has a HiDPI panel that needs an explicit scale, and only ASAHI has a US Apple keyboard (`xkbRulesLayout`).
- **A per-host driver package choice lives in the host's config module, not in the cross-host driver aspect.** `NIXPC` names `hardware.nvidia.package` explicitly in `nixpcConfiguration.nix` — a channel, so it floats with the nixpkgs pin; it is named at all so the branch is a deliberate choice rather than a default nobody looked at. At the 2026-10-14 pin it is `nixpkgs.latest`, which nixpkgs defines as `selectHighestVersion production new_feature` and which resolves to `615.78.08` (`production`/`stable` = `595.104.02`, `legacy_580` = `580.178.04`). Being a compound, `latest` re-points whenever the flake's nixpkgs advances `new_feature`; name `new_feature` to hold the branch steady, `production` to return to 595.x. `system/drivers/nvidia.nix` assigns **no** package for the same reason, so a host without a line of its own still gets whatever nixpkgs calls production. `beta` (`595.45.04`) and `vulkan_beta` (`595.44.09`) are **older** than production — downgrades, not options. The driver-side defects traded away by the branch move — vkd3d-proton refusing DX12 `WaveSize(64)` compute shaders (`Failed to create Vulkan compute pipeline, hr 0x80070057`) and a `libnvidia-gpucomp` compile spin — are recorded in `artifacts/dawnwalker-crash-report.html`.
- **nixos-hardware profiles are the one machine-fact shape that is spliced, not assigned.** `_hardware-profiles-settings.nix` is a function `{ self, ... }: [ …modules ]` that looks keys up in `self.nixosHardwareProfiles` (`system/hardware-profiles`), and the host's `default.nix` appends the list to `modules`: `modules = with self.nixosModules; [ … ] ++ hardwareProfiles;`. It cannot be an option, because a NixOS module cannot import conditionally on its own `config` and the upstream profiles set their values unconditionally — see the full reasoning and the per-host coverage matrix in `modules/system/hardware-profiles/AGENTS.md`.
- **ASAHI is local-build only; the distributed link's client half is retired.** `NIXPC` still imports `remoteBuilder`, but `ASAHI` no longer imports `distributedBuilds`, and `asahiConfiguration.nix` forces `nix.buildMachines = lib.mkForce [ ]`. That force is the contract, not the missing import: it holds even if a future module, overlay, or `nix.extra-platforms` reintroduces a builder. Nothing is gained by reinstating the link — the Mac already advertises `big-parallel` (nixpkgs' default `nix.settings.system-features`), which is the only feature gate that matters, so `linux-asahi`/`uboot-asahi`/`m1n1` build on the Mac whether or not NIXPC exists. Reinstating it would re-add the `/root/.ssh/remotebuild` key install step and make a dead tailnet break builds (an unreachable listed machine fails its jobs rather than degrading to local).
- **`tailscale` is imported by both hosts:** the module enables `services.tailscale` (tailscaled). Auth is interactive, so run `sudo tailscale up` once per machine after the switch that adds the module.
- **`inputs.asahi` must follow nixpkgs** (`inputs.nixpkgs.follows = "nixpkgs"` in `flake.nix`) — otherwise apple-silicon packages resolve against the wrong `nixpkgs` and break cross-machine eval (issue #16).
- **Asahi bootchain is uncached** (`nixos-apple-silicon.cachix.org` excludes `linux-asahi`/`uboot-asahi`/`m1n1`) — every `asahi` input bump rebuilds ~4 heavy derivations locally; plan reboot via `/run/reboot-required` (issue #72/#73).

## Work Guidance
- New host: create `hosts/<HOST>/default.nix` with `flake.nixosConfigurations.<HOST>`; start from `NIXPC` or `ASAHI` template; always include `hardwareFromMachine` first.
- Per-host settings that differ (e.g. Noctalia): keep in `_noctalia-settings.nix` or similar `_*` file and import explicitly.
- Record rescue/rollback steps in `RESCUE.md` (see `ASAHI/RESCUE.md`).
- Do not duplicate `docker` module import — `act` already pulls it via `desktop`.

## Verification
- `nix-instantiate --parse modules/hosts/<HOST>/default.nix`
- `nix eval .#nixosConfigurations.<HOST>.config.system.build.toplevel.drvPath --impure` (placeholder warning is expected off-machine)
- `nix run .#verify -- --host <HOST>` — hardware gate checks native vs cross-machine branch.
