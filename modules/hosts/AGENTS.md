# hosts — host presets

## Purpose
One directory per machine producing `flake.nixosConfigurations.<HOST>`. Assembles `self.nixosModules` bundles + features into a concrete NixOS system. Two hosts: `NIXPC` (`x86_64-linux`, MangoWM, NVIDIA) and `ASAHI` (`aarch64-linux`, MangoWM + Niri, Apple Silicon).

## Ownership
- `NIXPC/` — `default.nix` (system assembly), `nixpcConfiguration.nix` (host-specific NixOS config), `_noctalia-settings.nix`, `_mango-settings.nix`, `RESCUE.md` if present.
- `ASAHI/` — `default.nix`, `asahiConfiguration.nix`, `RESCUE.md`, `_noctalia-settings.nix`, `_mango-settings.nix`.

## Local Contracts
- **Assembly is `nixosSystem`:** each `default.nix` calls `inputs.nixpkgs.lib.nixosSystem { system = "<arch>-linux"; modules = with self.nixosModules; [ … ]; }`.
- **`hardwareFromMachine` gate:** every host's first module is `(self.lib.hardwareFromMachine "<system>")` from `modules/system/core/default.nix`. On the native machine with `--impure`, it imports `/etc/nixos/hardware-configuration.nix` (real `fileSystems."/"` by-uuid, `nixpkgs.hostPlatform` from hardware). Anywhere else (CI, other host, sandbox/`CI=1`/`NIX_BUILD_TOP`) it uses a placeholder root fs — evaluation succeeds, deploy does not. The `verify.nix` hardware gate enforces this.
- **`--impure` required for deploy:** `sudo nixos-rebuild switch --impure --flake ~/.config/dendritic#<HOST>` — evaluated elsewhere shows the documented placeholder warning.
- **Shared base is `desktop`:** both hosts import `desktop` (from `attrs/desktop` → `core` + `network` + `audio` + `homeManager` + `act` + `waylandBase` + `computerUse` + `stylix` + `nautilus` + common `environment.systemPackages` + `allowUnfree`). Host `default.nix` then adds its compositor, drivers, and extras. Neither `stylix` nor `nautilus` is host-specific, so they live in the bundle rather than in a host's module list.
- **Per-host deltas:**
  - `NIXPC`: `nixpcConfiguration`, `nixpcDesktop`, `nvidiaDrivers`, `gaming`, `mango`, `wayland`, `noctaliaGreeter --session Mango`, `mcpContainers` (via `desktop→act→docker`; do not re-import `docker`), `herdr-web` with `services.herdr-web.tailscaleServe.enable = true` (the bridge reaches the phone over tailnet HTTPS), `herdr-web-ui` with `services.herdr-web-ui.tailscaleServe.enable = true` (the second, richer herdr client — chat view, file viewer, remote PCs, push alerts — on its own port, published alongside the first), `remoteBuilder` (the `remotebuild` build account, issue #209; dormant — ASAHI no longer schedules work here, see the build-link contract below), `paseo` (the daemon and web UI container behind `tailscale serve`, issue #201), `wayfinder-dashboard` (Wayfinder Relay user service behind `tailscale serve`, one Herdr workspace per project), `flatpakNixpc` (OBS Studio, Sober, and the pinned Spotifast bundle — all x86_64-only).
  - `ASAHI`: `asahiConfiguration`, `asahiPlatform` (apple-silicon support), `widevine`, `niri`, `mango`, `wayland`, `noctaliaGreeter --session Mango`, `stability`/`timeSync`/`flatpakAsahi`/`obs` (the Flatpak feature contributes **no** apps on ASAHI: every app in it is x86_64-only and aarch64 has none). It builds **everything locally** — `distributedBuilds` was removed and `nix.buildMachines` is forced empty, so no derivation this host installs can be scheduled off-box.
- **The three agent-facing servers are NIXPC-only, and the import must stay that way.** `herdr-web`, `herdr-web-ui`, and `wayfinder-dashboard` each ship their home-manager module from their own NixOS module (`home-manager.sharedModules`), so `hosts/ASAHI/default.nix` must not import them. The herdr bridges grant terminal control of every pane to whoever reaches them, and ASAHI runs no agents. `herdr-web-ui` is doubly NIXPC-only: its `node_modules` FOD hash is the tree bun resolves for x86_64, so ASAHI's closure failed to build it with a hash mismatch. The `herdr` binary itself stays in `attrs/desktop`'s shared `systemPackages` — it is a multiplexer client, not a server.
- **Per-host keyboard layout is a three-channel contract.** `system/core/locale.nix` holds the `mkDefault` `gb`/`uk` pair for NIXPC. ASAHI overrides all three with `us`: `services.xserver.xkb.layout`, `console.keyMap` (`hosts/ASAHI/default.nix`), and `dendritic.mango.xkbRulesLayout` (`hosts/ASAHI/_mango-settings.nix`), because the compositor's own keymap is the one that types. `us` with no variant is US ANSI. No `evremap` — the `gb` workaround (Ctrl+2 for @, Option+3 for #) is gone with the `gb` keymap.
- **Both hosts import `wayland` (`system/wayland.nix`) and neither imports `portals` directly:** `wayland` imports `portals`, so it is the single entry point for the portal stack. The module is written against MangoWM, which both hosts run; the `niri` module on ASAHI is installed but not the session in use.
- **Flatpak is a feature, not a system module:** each host imports the `flatpak` feature (`flatpakNixpc` / `flatpakAsahi`), which carries the per-host Flatpak apps on top of the shared OBS aspect. `system/flatpak/` no longer exists.
- **Machine facts of a shared feature live in `_<feature>-settings.nix`:** the host module imports the file and assigns it to the feature's options. `mango` (issue #245) is the reference: each host imports `_mango-settings.nix` into `dendritic.mango`, because mango runs on both hosts but only NIXPC has two monitors and an NVIDIA GPU, only ASAHI has a HiDPI panel that needs an explicit scale, and only ASAHI has a US Apple keyboard (`xkbRulesLayout`).
- **ASAHI is local-build only; the distributed link's client half is retired.** `NIXPC` still imports `remoteBuilder`, but `ASAHI` no longer imports `distributedBuilds`, and `asahiConfiguration.nix` forces `nix.buildMachines = lib.mkForce [ ]`. That force is the contract, not the missing import: it holds even if a future module, overlay, or `nix.extra-platforms` reintroduces a builder. Nothing is gained by reinstating the link — the Mac already advertises `big-parallel` (nixpkgs' default `nix.settings.system-features`), which is the only feature gate that matters, so `linux-asahi`/`uboot-asahi`/`m1n1` build on the Mac whether or not NIXPC exists. Reinstating it would re-add the `/root/.ssh/remotebuild` key install step and make a dead tailnet break builds (an unreachable listed machine fails its jobs rather than degrading to local).
- **`tailscale` is imported by both hosts:** the module enables `services.tailscale` (tailscaled). Auth is interactive, so run `sudo tailscale up` once per machine after the switch that adds the module.
- **`inputs.asahi` must follow nixpkgs** (`inputs.nixpkgs.follows = "nixpkgs"` in `flake.nix`) — otherwise apple-silicon packages resolve against the wrong `nixpkgs` and break cross-machine eval (issue #16).
- **Asahi bootchain is uncached** (`nixos-apple-silicon.cachix.org` excludes `linux-asahi`/`uboot-asahi`/`m1n1`) — every `asahi` input bump rebuilds ~4 heavy derivations locally; plan reboot via `/run/reboot-required` (issue #72/#73).

## Work Guidance
- New host: create `hosts/<HOST>/default.nix` with `flake.nixosConfigurations.<HOST>`; start from `NIXPC` or `ASAHI` template; always include `hardwareFromMachine` first.
- Per-host settings that differ (e.g. Noctalia): keep in `_noctalia-settings.nix` or similar `_*` file and import explicitly.
- Record rescue/rollback steps in `RESCUE.md` (see `ASAHI/RESCUE.md`).
- Do not duplicate `docker` module import — `act` already pulls it via `desktop`.

## Verification
- `nix-instantiate --parse modules/hosts/<HOST>/default.nix`
- `nix eval .#nixosConfigurations.<HOST>.config.system.build.toplevel.drvPath --impure` (placeholder warning is expected off-machine)
- `nix run .#verify -- --host <HOST>` — hardware gate checks native vs cross-machine branch.
